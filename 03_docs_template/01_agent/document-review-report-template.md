# 문서 리뷰 리포트

> 이 리포트는 문서를 검토한 결과다.
> 원문의 사실, 수치, 정책, 기술적 의미는 변경하지 않았다.
> 짧고 쉬운 단어를 사용한다. 전문 용어가 필요하면 처음 나올 때 쉬운 말로 설명한다.
> 결과를 먼저 쓴다. 한 문장에는 한 가지 내용만 담고, 불필요한 배경 설명은 뺀다.

## 1. 검토 대상

- 문서: `[파일 경로 또는 문서명]`
- 문서 유형: `[기능 매뉴얼 / 외부 기능 명세서 / 개발 보고서 / ...]`
- 주 독자: `[독자]`
- 독자 목표: `[문서를 읽은 뒤 하려는 일]`

## 4. 잘된 점

## 5. 수정 제안

| ID | 우선순위 | 위치 | 문제 | 제안 |
| --- | --- | --- | --- | --- |
| `OUTLINE-01` | 높음 | `## 사용 방법` | 선행 조건이 사용 단계 뒤에 있음 | 선행 조건을 사용 방법 앞으로 이동 |
| `TYPE-01` | 보통 | `## 오류 대응` | 오류별 대응 방법이 없음 | 자주 발생하는 오류와 대응 방법 추가 |

- **높음**: 독자가 목적을 달성하지 못하거나 오해할 수 있다.
- **보통**: 정보를 찾거나 이해하기 어렵다.
- **낮음**: 더 읽기 쉽게 만들 수 있다.

## 6. 제안 구조

> 구조 변경이 필요할 때만 작성한다.

```text
문서 제목
├─ 개요
├─ 사용 전 확인 사항
├─ 사용 방법
├─ 오류 대응
└─ 관련 정보
```
