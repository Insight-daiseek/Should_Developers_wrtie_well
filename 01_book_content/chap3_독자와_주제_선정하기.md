## 3.1. 독자 맞춤형 문서 만들기

정보를 무작정 늘리면 문서는 읽기 어려워지고, 필요한 정보도 찾기 힘들다. 

따라서 독자 주제와 범위를 가능한 좁히는게 이득이고, 아래와 같은 장점이 따른다.

- 문서 구성이 단순해짐

- 독자 맞춤 구성 가능

- 독자 눈높이에 맞춰 세분화된 설명 가능


## 3.2. 문서 목적을 명확히 하기

1. 독자를 선정한다. 개발자, 디자이너, 프로덕트 매니저 등등...

2. 주제를 좁힌다. 독자 먼저 선정하면 어떤 수준의 정보를 담을지 정하기 쉽다. 


## 3.3. 독자 이해하기

독자 이해를 위해 파악해야 할 점 3가지

1. 독자 지식 수준 

- Ex. 개발자 관련 문서일 경우
    - 프로덕트에 대한 지식 : 각 기능의 개념, 용어, 조작법 등을 어느 정도 이해하고 있는가?
    - 기술에 관한 지식 : 기술 요소(PC 조작에 대한 이해, 계정이나 접근 권한 등)
    - 업무에 관한 지식 : 도메인 지식

위 3가지를 세부적으로 파악하면 독자 맞춤 설명 하기 쉬워진다.

Ex. 회계 애플리케이션을 금융권 회사에 납품할 때

2. 독자의 목적

하나의 추상화된 목적을 세분화해서 생각하기

- 프로덕트 사용 방법을 알고 싶다.
    - 프로덕트 도입 방법을 알고 싶다.
    - 기능 사용법을 알고 싶다.
    - 오류 발생 시 대처법을 알고 싶다.
    ...


3. 독자의 직무와 역할

Ex. 웹 애플리케이션 개발시 프로그래머, QA 엔지니어, 디자이너 별로 세분화되어 기술 명세 작성


## 3.4. 독자를 이해하기 위한 정보원

독자를 이해하는 방법

1. 관계자에게 물어보기

- 최근 팀에 합류한 사람

- 고객 지원팀 / 관리팀

2. 문의 내용 참고하기

- 예상 독자층에게 들어온 문의 내용 참고하기


## 3.5. 독자와 주제 좁히기

독자와 주제 좁히기가 어렵다면 아래 요소를 지켜보자.

1. 문서를 4단 구조로 구성

2. 독자마다 필요 정보가 크게 다르다면, 그냥 여러 문서를 만들자.

```
- Depth 1 : 주제
    - Depth 2 : 소제목
        - Depth 3 : 패러그래프 
            - Depth 4 : 도입부, 주장문    
    - Depth 2 : 소제목
        - Depth 3 : 패러그래프 
            - Depth 4 : 도입부, 주장문
    ...

```
