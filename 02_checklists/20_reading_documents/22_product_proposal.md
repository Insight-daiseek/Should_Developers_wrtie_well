# 프로덕트·기술 제안서 체크리스트

적용 대상: 문제 해결 방안, 제품 변경, 기술 설계의 채택을 설득하고 구현 전에 필요한 합의를 얻기 위한 문서.

## 1. 문제와 목표

- [ ] 해결하려는 문제와 현재 상태, 문제의 영향을 구체적으로 설명하는가?
- [ ] 문제의 근거, 사실, 가정, 확인되지 않은 내용을 구분하는가?
- [ ] 제안의 목표와 성공 기준을 설명하는가?
- [ ] 제안의 범위와 범위 밖의 내용을 명시하는가?

## 2. 제안 내용과 설계

- [ ] 제안 내용이 문제와 직접 연결되는가?
- [ ] 제품 또는 사용자 관점의 변화와 기대 효과를 설명하는가?
- [ ] 제안하는 기술 구조와 주요 구성 요소의 책임을 이해하기 쉽게 설명하는가?
- [ ] 데이터 흐름, 요청 흐름, 상태 변화 중 필요한 흐름을 설명하는가?
- [ ] 외부 시스템, 내부 모듈, 데이터 저장소 등 주요 의존성을 명시하는가?

## 3. 대안, 영향, 위험

- [ ] 검토한 대안과 각 대안의 장단점을 설명하는가?
- [ ] 제안한 방안을 선택한 이유가 목표와 제약에 연결되는가?
- [ ] 기존 시스템, API, 데이터, 사용자에게 미치는 영향을 설명하는가?
- [ ] 보안, 성능, 안정성, 운영 측면의 요구사항을 필요한 범위에서 다루는가?
- [ ] 마이그레이션, 호환성, 되돌리기 방법이 필요하면 설명하는가?
- [ ] 알려진 위험, 미해결 문제, 확인이 필요한 가정과 대응책을 명시하는가?

## 4. 실행과 검증

- [ ] 구현을 위한 주요 작업과 작업 순서, 일정, 참여 인력, 비용을 제시하는가?
- [ ] 기대 효과, 검증 기준, 성공 기준을 구분하는가?
- [ ] 설계와 제안이 성공했는지 확인할 테스트·측정·검증 방법을 제시하는가?
- [ ] 독자에게 요청하는 의사결정, 승인 또는 다음 행동을 명확히 제시하는가?

## 예시 구조

```text
프로덕트·기술 제안서
├─ 요약 및 결정 요청
│  ├─ 제안 내용
│  ├─ 핵심 결정과 기대 효과
│  └─ 요청하는 승인
├─ 문제와 배경
│  ├─ 문제의 영향
│  └─ 근거와 가정
├─ 목표와 범위
│  ├─ 목표와 성공 기준
│  └─ 범위 밖의 내용
├─ 제안 내용과 설계
│  ├─ 제품·사용자 관점의 변화
│  ├─ 전체 구조와 구성 요소의 책임
│  ├─ 데이터 또는 요청 흐름
│  └─ 주요 의존성
├─ 대안과 선택 이유
├─ 영향과 위험
│  ├─ 기존 시스템, API, 데이터, 사용자 영향
│  ├─ 보안·성능·안정성·운영 고려 사항
│  ├─ 마이그레이션·호환성·롤백
│  └─ 미해결 문제와 대응책
└─ 실행과 검증 계획
   ├─ 주요 작업, 순서, 일정, 인력, 비용
   └─ 테스트·측정·검증 방법
```
