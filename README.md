# 개발자가 문서 작성도 잘해야 하나요?

개발자가 문서를 검토하고 작성할 때 사용할 체크리스트, 템플릿, 코딩 에이전트 지침을 모은 프로젝트입니다.

문서 작성이 어려운 개발자에 초점을 두었습니다. 문서 구조 설계, 문서 리뷰에 사용할 수 있습니다. 

개발자가 문서 작성에 능숙해지고, 이 도구를 쓰지 않는 것을 최종 목적으로 삼았습니다.


원전: 《개발자가 문서 작성도 잘해야 하나요?》

- 저자: 나카타 나오히로
- 옮김: 김정민

## 프로젝트 개요

### 대상 사용자

문서를 검토하거나 작성하는 개발자

### 제공 자료

- 문서 유형별 체크리스트
- 코딩 에이전트용 문서 리뷰 지침
- 에이전트 작업 결과를 알리는 출력 양식
- 문서 구조를 설계하기 위한 사용자용 양식

### 현재 기능 제공 범위

Claude와 Codex 같은 코딩 에이전트 사용을 전제로 합니다. 로컬 LLM을 직접 서빙하는 문서 리뷰 에이전트는 구현 계획에 없습니다.

## 빠른 시작 방법

### 필요한 환경

- 이 저장소의 파일을 읽을 수 있는 코딩 에이전트
- 검토하거나 수정할 문서

### 문서 리뷰 시작하기

1. 코딩 에이전트에게 [`04_agent_guideline/AGENTS_Doc_Review.md`](04_agent_guideline/AGENTS_Doc_Review.md)를 읽도록 요청합니다.
2. 검토할 문서의 경로와 작업 목적을 전달합니다.
3. 에이전트의 리뷰 결과를 확인하고, 필요한 수정 작업을 요청합니다.

예시 요청:

```text
04_agent_guideline/AGENTS_Doc_Review.md를 읽고, example.md를 제품 매뉴얼로 검토해 주세요.
출력 양식은 `document-review-report-template.md` 을 사용해주세요.
```

## 사용 방법

### 사용자 문서 작성

본 문서 작성 전 `03_docs_template` 경로의 세 가지 문서를 작성합니다. 문서 작성 전 내용 구성은 독자 고려 / 주제 구성이 주를 이룹니다.

코딩 에이전트가 세 문서를 참고해 문서 구조 설계에 도움을 줄 수 있습니다. 



### 문서 유형 선택

문서가 필요한 정보를 찾아 읽는 문서라면 사전형 체크리스트를 사용합니다. 예를 들어 제품 매뉴얼, 절차서, API 명세서가 있습니다.

문서를 처음부터 끝까지 읽으며 내용을 이해하는 문서라면 읽기형 체크리스트를 사용합니다. 예를 들어 개발 보고서, 제안서, 기술 블로그가 있습니다.

에이전트는 `AGENTS_Doc_Review.md`의 순서에 따라 공통 체크리스트와 문서 유형별 체크리스트를 함께 적용합니다.

### 에이전트 출력 양식

`03_docs_template/01_agent/`에는 작업 목적에 맞는 출력 양식이 있습니다.

| 작업 | 양식 |
| --- | --- |
| 문서 품질 검토 | `document-review-report-template.md` |
| 구현·수정 완료 보고 | `task-completion-report-template.md` |
| 원인 조사와 진단 | `investigation-report-template.md` |
| 구현 전 계획 합의 | `implementation-plan-template.md` |
| 변경 코드 검토 | `code-review-report-template.md` |
| 테스트 결과 보고 | `verification-report-template.md` |
| 사용자 결정 요청 | `blocker-decision-request-template.md` |

모든 양식은 결과를 먼저 알리고, 한 문장에 한 가지 내용만 담도록 구성했습니다.

## 프로젝트 구조

```text
Should_Developers_Write_Well/
├─ 01_book_content/       # 책 정리본
├─ 02_checklists/         # 문서 유형별 체크리스트
│  ├─ 00_common/          # 모든 문서의 공통 기준
│  ├─ 10_reference_documents/ # 사전형 문서 기준
│  └─ 20_reading_documents/   # 읽기형 문서 기준
├─ 03_docs_template/      # 문서 작성과 에이전트 출력 양식
│  ├─ 01_agent/           # 에이전트용 출력 양식
│  └─ 02_users/           # 문서 작성자용 구조 설계 양식
├─ 04_agent_guideline/    # 문서 리뷰 에이전트 지침 / AGENTS.md & CLAUDE.md 
└─ docs/                  # 기능 구현 문서와 에이전트 보고서 저장 위치
```

## 문서 유형 안내

### 외부 기능 명세서와 기능 구현 명세서

외부 기능 명세서는 외부 사용자, 프론트엔드 개발자, 고객이 기능을 사용할 때 필요한 정보를 설명합니다. API 요청과 응답, 오류, 인증, 호환성 등이 대상입니다. 내부 DB 구조와 로직은 다루지 않습니다.

기능 구현 명세서는 백엔드 개발자, QA, 운영자가 기능을 구현하고 검증할 때 필요한 정보를 설명합니다. 처리 흐름, 상태 변화, 예외와 복구 방법, 테스트 기준 등 내부 구현 정보를 다룹니다.

기능 구현 내용이 적거나 팀 규모가 작다면 두 문서를 하나로 합칠 수 있습니다.

### 읽기형 문서와 사전형 문서

읽기형 문서는 독자가 처음부터 끝까지 읽으며 내용을 이해하는 문서입니다. 보고서, 제안서, 기술 블로그가 해당합니다.

사전형 문서는 독자가 특정 정보를 찾기 위해 읽는 문서입니다. API 명세서와 코딩 가이드가 해당합니다.

두 유형 모두 제목과 소제목에 주제를 분명히 적어야 합니다. 특히 사전형 문서는 필요한 정보를 빠르게 찾을 수 있어야 합니다.
